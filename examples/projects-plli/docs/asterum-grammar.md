# 아스테룸 문자 해석 규칙

## 기준 자산

아스테룸 기본 문자는 `assets/asterum/characters/svg`의 자음 14개와 모음 14개다. 문자와 한글 자모의 대응은 `assets/asterum/mapping/asterum.mapping.v1.json`이 단일 기준이다.

SVG 파일명은 원본을 사람이 검토하기 위한 정보일 뿐이다. 서비스와 학습 파이프라인은 파일명을 해석하지 않고 매핑의 `glyph_id`와 `ko_jamo`를 사용한다.

## 해석 순서

1. 사진에서 텍스트 영역과 문자 영역을 찾는다.
2. 문자를 읽기 순서대로 정렬한다.
3. 각 문자 이미지를 28개 `glyph_id` 중 하나로 분류한다.
4. `glyph_id`를 한글 호환 자모로 변환한다.
5. 자모 열을 초성·중성·종성 규칙으로 음절 조합한다.

예를 들어 `ㄱ ㅑ ㅇ ㅗ ㅐ`는 `ㄱ+ㅑ`, `ㅇ+ㅗ+ㅐ`로 나뉜다. `ㅗ+ㅐ`는 복합 모음 `ㅙ`가 되므로 결과는 `갸왜`다.

현재 조합기는 다음 규칙을 결정적으로 처리한다.

- 한글의 7개 복합 모음
- 11개 겹받침
- 음절 시작의 기본 자음 쌍 `ㄱ+ㄱ`, `ㄷ+ㄷ`, `ㅂ+ㅂ`, `ㅅ+ㅅ`, `ㅈ+ㅈ`을 각각 된소리 초성 `ㄲ`, `ㄸ`, `ㅃ`, `ㅆ`, `ㅉ`으로 조합
- 종성의 `ㄱ+ㄱ`, `ㅅ+ㅅ`을 각각 쌍받침 `ㄲ`, `ㅆ`으로 조합

예를 들어 `ㄷ ㄷ ㅡ ㅅ`은 `뜻`, `ㅂ ㅏ ㄱ ㄱ`은 `밖`, `ㅇ ㅣ ㅅ ㅅ`은 `있`이 된다. 초성이나 중성이 없는 불완전한 열은 임의로 보정하지 않고 위치와 오류 코드를 반환한다.

## 쌍자음과 음절 경계

된소리 초성은 같은 기본 자음 두 개 뒤에 모음이 오는 경우에만 합친다. 다만 평평한 자모 열만으로는 모든 음절 경계를 알 수 없다. 예를 들어 `ㅇ ㅏ ㄱ ㄱ ㅏ`는 `악가`와 `아까`가 모두 가능하다.

현재 조합기는 기존의 왼쪽 우선 규칙에 따라 앞 자음을 앞 음절의 받침으로 사용해 `악가`로 조합한다. 문맥이나 사전으로 `아까`를 추측하지 않는다. 다른 해석을 정확히 표현하려면 향후 OCR 결과 계약에 음절 경계 정보를 추가해야 한다.

조합 결과에는 `AMBIGUOUS_SYLLABLE_BOUNDARY` 경고와 문제가 시작된 자모 위치를 함께 반환한다. UI는 기본 결과만 확정값처럼 표시하지 않고 사용자가 음절 경계를 확인할 수 있게 한다.

## 한글에서 아스테룸 문자로 역변환

한글 입력을 아스테룸 문자로 바꿀 때는 완성형 음절을 기본 자모로 분해한다. 별도 쌍자음 글리프가 없으므로 된소리 초성은 다음처럼 기본 자음 두 개로 되돌린다.

- `ㄲ → ㄱ+ㄱ`
- `ㄸ → ㄷ+ㄷ`
- `ㅃ → ㅂ+ㅂ`
- `ㅆ → ㅅ+ㅅ`
- `ㅉ → ㅈ+ㅈ`

종성 `ㄲ`, `ㅆ`도 각각 `ㄱ+ㄱ`, `ㅅ+ㅅ`으로 분해한다. 예를 들어 `까 → ㄱ ㄱ ㅏ`, `뜻 → ㄷ ㄷ ㅡ ㅅ`, `밖 → ㅂ ㅏ ㄱ ㄱ`, `있 → ㅇ ㅣ ㅅ ㅅ` 순서로 아스테룸 기본 글리프를 렌더링한다. 역변환 구현 시 이 사례들의 왕복 테스트를 필수로 둔다.

## 아직 정해야 하는 규칙

- 실제 사진에서 단어·음절·문자 간격을 구분하는 기준
- 줄바꿈과 문장부호를 보존하는 방식
- 띄어쓰기가 없거나 문자끼리 닿은 경우의 후보 선택 방식
- 영문 결과를 위한 승인된 매핑 또는 로마자 표기 규칙

이 항목은 실제 문장 이미지 샘플을 확인한 뒤 테스트 사례와 함께 확정한다. 생성형 AI나 한국어 사전으로 인식 결과를 자동 보정하지 않는다.
